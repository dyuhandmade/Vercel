1. Technical Executive Summary
The DYU Handmade website will use a headless commerce architecture: Shopify owns products, variants, pricing, inventory, cart and checkout; a custom Next.js application owns presentation, narrative storytelling, motion, 3D experiences, SEO delivery and analytics. This separation allows the client to keep Shopify's mature merchant operations while removing the visual and interaction limits of a conventional theme storefront.
The reference frontend uses Next.js App Router with TypeScript and Tailwind CSS. Server-rendered React components will deliver indexable narrative and commerce content. Client components will be reserved for interactions such as menu state, product gallery, filter controls, cart actions, scroll choreography and 3D scenes. Shopify Storefront API will be used for public commerce queries/mutations. Rich narrative data will be modeled through Shopify metafields/metaobjects and exposed to the Storefront API with appropriate storefront access.

4. Shopify Integration
4.1 API model
The storefront will integrate with Shopify's GraphQL Storefront API. Shopify documents the Storefront API as framework-agnostic and suitable for custom storefronts, including products, collections, search and cart. The cart object exposes a checkoutUrl that redirects the buyer to Shopify's web checkout. Storefront API versions are released on a schedule; the implementation must pin an explicit supported version rather than using an unversioned endpoint.

8. Cart and Checkout

Figure 5. Headless cart and Shopify checkout handoff.
8.1 Cart state
Create cart lazily on first add-to-bag or earlier only if required.
Persist full cart ID token/secret safely according to Shopify requirements; do not parse or assume token length/format.
Store cart identifier in an appropriate same-site cookie or client storage strategy chosen during implementation; prevent accidental cross-user leakage.
Re-fetch cart on cart page/open when stale or after mutation.
Handle merchandise changes, sold-out lines, price changes and userErrors explicitly.
8.2 Checkout
The final transaction is completed using the checkout URL returned on the Shopify cart. This keeps payment, tax, address, shipping and Shopify-supported checkout controls in Shopify. The DYU storefront is responsible for creating the correct cart and transitioning the buyer cleanly to checkout.

10. Design System and Frontend Components
10.1 Token groups
Color: ivory, beige, sage, olive, deep forest, terracotta, walnut, charcoal and semantic states.
Typography: display serif, body sans, handwritten accent used only as controlled artwork/font asset if licensed.
Spacing: 4/8-based scale with editorial large gaps.
Radius: subtle rounded cards/controls; avoid generic fully-pill UI everywhere.
Shadow: soft material depth, not strong SaaS-style elevation.
Motion tokens: fast UI, normal UI, editorial reveal, page transition and scroll choreography.
Z-index layers: base, sticky nav, overlays, cart/search, 3D canvas, modals.

11. Search, Filtering and Navigation
Initial implementation should use Shopify-native search/product querying unless catalogue scale, merchandising needs or relevance requirements justify a dedicated search provider. Architecture should hide search behind an internal interface so a future engine can replace it without rewriting page UI.

12. SEO and Structured Data
Use Next.js metadata APIs for canonical title, description, social previews and robots directives.
Generate canonical URLs consistently across product/collection query states.
Server-render Product JSON-LD with actual price/availability data; do not invent ratings unless verified review data is available.
Render BreadcrumbList where page hierarchy exists.
Render Article markup for journal entries where appropriate.
Generate sitemap indexes/pages appropriate to catalogue size and include only canonical public URLs.
Ensure filter parameters do not create uncontrolled indexable duplicate pages unless intentionally designed.
Use optimized image alt text and descriptive filenames where practical.

15. Accessibility Engineering
WCAG-oriented semantic HTML and keyboard-first control implementation.
No critical action depends only on hover.
All custom variant, filter, gallery and ingredient controls expose name/state/role to assistive technology.
Focus management for menu, cart drawer, search overlay and dialogs.
Reduced-motion branch for GSAP/Three scenes.
Canvas/3D scenes have equivalent HTML text content outside the canvas.
Color contrast and target-size QA on actual design tokens.
Automated accessibility checks supplemented by manual keyboard and screen-reader smoke tests.
